# figure-events Specification

## Purpose

Define role-based event generation and the extension of the `simulation.Event` struct with figure references.

## ADDED Requirements

### Requirement: Role-Based Event Generation

Each role SHALL implement event generation logic producing domain-specific events when a figure with that role ticks.

#### Scenario: Leader generates settlement events

- **WHEN** a figure with the Leader role processes a simulation year
- **THEN** the Leader SHALL generate 0 or more events from categories including Politics, Conflict, Settlement
- **THEN** each event description SHALL include the leader's name and settlement name
- **THEN** event generation SHALL be deterministic given the settlement's RNG state

#### Scenario: Explorer generates discovery events

- **WHEN** a figure with the Explorer role processes a simulation year
- **THEN** the Explorer SHALL generate 0 or more events from categories including Discovery
- **THEN** discovery events SHALL reference pointcrawl nodes when available
- **THEN** event generation SHALL be deterministic given the settlement's RNG state

#### Scenario: Roleless figures generate no events

- **WHEN** a figure without a role processes a simulation year
- **THEN** the figure SHALL NOT generate role-specific events
- **THEN** the figure MAY still generate personal events (birth of child, marriage) if eligible

### Requirement: Event Struct Extension for Figures

The `simulation.Event` struct SHALL include optional figure reference fields that are omitted when no figure is involved.

#### Scenario: Event with figure reference

- **WHEN** an event is generated by a figure's role
- **THEN** the event SHALL include a `figureId` field containing the figure's unique ID
- **THEN** the event MAY include `relatedFigures` IDs for secondary figures involved in the event
- **THEN** the event SHALL include a `settlementName` field identifying the figure's settlement

#### Scenario: Event without figure reference

- **WHEN** an event is generated by a system that does not involve figures (e.g., natural disaster, random encounter)
- **THEN** the `figureId`, `relatedFigures`, and `settlementName` fields SHALL be omitted from JSON serialization
- **THEN** the `FormatEvent` function SHALL produce the same output format as before (category + description)

#### Scenario: Backward compatibility

- **WHEN** a timeline.json generated without figure references is loaded by the updated system
- **THEN** events SHALL deserialize successfully with empty figure reference fields

### Requirement: Event Frequency Constraints

The system SHALL NOT generate a figure event every year for every figure. Event generation SHALL be sparse to keep the timeline readable.

#### Scenario: Sparse event generation

- **WHEN** a figure processes a year
- **THEN** the probability of generating an event SHALL be low enough that not every figure generates an event every year
- **THEN** significant events (death, succession, marriage) SHALL always generate events regardless of probability
- **THEN** routine events (daily governance, travel) SHALL be generated infrequently

### Requirement: Figure-Event Association in Export

The export system SHALL associate timeline events with the figures who generated or were involved in them.

#### Scenario: Figure chronicle section

- **WHEN** exporting a figure's character file to Obsidian
- **THEN** the file SHALL include a "Chronicle" section listing timeline events in which the figure appears (by `figureId` or `relatedFigures`)
- **THEN** events SHALL be listed chronologically with year and description
